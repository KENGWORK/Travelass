# LINE: ร้านอาหาร / สถานที่ที่อยากไป (เฟส 2 — สถานที่)

## Context

ต่อจาก spec เฟส 1 (ค่าใช้จ่าย), แพลน, การจอง (`2026-11-19-line-*-design.md`)
ให้เปิดดูร้านอาหาร (`restaurants`) และที่อยากไป (`wishlist`) ผ่าน LINE ระหว่างเดิน — เน้นรูป + ปุ่ม Maps

ผู้ใช้: กลุ่ม LINE 2 คน + บอท · ทริปเป้าหมาย = `status === "active"`

## ขอบเขต

| การกระทำ | LINE |
|---|---|
| ดูรายการ / กรอง / ค้น | ✅ |
| ดูรูป (แตะขยายเต็มจอ) | ✅ |
| สลับ ไปแล้ว ⇄ ยังไม่ไป | ✅ (`visited`) |
| เพิ่ม / แก้ / ติดดาว / ลบ | ❌ แอปเท่านั้น |
| เรียงตามระยะใกล้ตัว | ❌ ไม่ทำ |

reply เท่านั้น, ปุ่ม postback (เหมือนเฟสก่อน)

## คำสั่ง

แยก 2 ชุดตามแอป

| คำหลัก | แหล่งข้อมูล |
|---|---|
| `ร้าน` `ร้านอาหาร` `กิน` | `restaurants` |
| `ที่เที่ยว` `อยากไป` `สถานที่` | `wishlist` |

ข้อความเข้าข่ายเมื่อ **ขึ้นต้นด้วยคำหลัก** (ตัด `ขอดู` `ขอ` นำหน้าได้ เหมือน spec การจอง) — match คำยาวก่อน (`ร้านอาหาร` ก่อน `ร้าน`)

**ตัวกรองหลังคำหลัก:**
| คำ | ผล |
|---|---|
| `ต้องลอง` `ดาว` | `must_try` (ร้าน) / `star` (ที่เที่ยว) = true |
| `ยังไม่ไป` | `visited` = false |
| `ไปแล้ว` | `visited` = true |
| คำอื่นที่เหลือ | คำค้น → contains (case-insensitive) ใน `name` `area` `note` |

ตัวอย่าง: `ร้าน` · `ร้าน มงก๊ก` · `ร้าน ต้องลอง` · `ร้าน ยังไม่ไป` · `ร้าน ห่าน` · `ที่เที่ยว central` · `อยากไป ดาว`

## ชนกับการบันทึกค่าใช้จ่าย

ใช้กฎเดียวกับ spec การจอง: เข้าข่ายคำสั่ง **และมีตัวเลข** → ถามกลับทุกครั้ง `[💸 บันทึกค่าใช้จ่าย] [🍜 ค้นร้าน | 📍 ค้นที่เที่ยว]`
สำคัญกับคำหลัก `กิน` เป็นพิเศษ — `กินข้าว 120` ต้องไม่หายเงียบเป็นการค้นร้าน

## ผลค้น

| เจอ | ตอบ |
|---|---|
| 0 (มีคำค้น/ตัวกรอง) | "ไม่เจอ '{คำค้น}'" + quick reply ย่านที่มีจริง (≤ 13) |
| 0 (รายการว่างทั้งหมด) | "ยังไม่มีร้าน/ที่เที่ยวในทริปนี้" + [เปิดแอป] |
| 1 (มีคำค้น) | carousel การ์ดสถานที่ใบเดียว (ไม่มีการ์ดหัว) |
| ≥ 1 (ไม่มีคำค้น) / ≥ 2 | carousel: การ์ดหัว + การ์ดสถานที่ |

## Carousel

**เรียง:** ติดดาว (`must_try`/`star`) ก่อน → `visited` false → `visited` true · ภายในกลุ่มเรียงตามชื่อ

**แบ่งหน้า:** การ์ดหัว 1 + สถานที่ ≤ 10 + (ถ้าเหลือ) การ์ด "ดูต่อ ({x})" = ≤ 12 bubble · หน้า 2+ ไม่มีการ์ดหัว (สถานที่ ≤ 11 + ดูต่อ)

### การ์ดหัว

```
🍜 ร้านอาหาร · {n}          (📍 ที่อยากไป · {n})
ต้องลอง {a} · ยังไม่ไป {b} · ไปแล้ว {c}
[ตัวกรองปัจจุบัน ถ้ามี: "กรอง: Mong Kok"]
ปุ่ม: ย่านที่มีมากสุด ≤ 4 ปุ่ม "{area} ({count})"
      [⭐ เฉพาะต้องลอง]  (ถ้ากรองอยู่ → [ล้างตัวกรอง])
```

### การ์ดสถานที่

```
hero:  photo_ids[0] — แตะ = เปิดรูปเต็ม (uri /api/img/{id})
       ป้ายมุมซ้ายบน: "⭐ ต้องลอง" | "✓ ไปแล้ว"
       ป้ายมุมขวาล่าง: "แตะเพื่อขยาย"
ชื่อ:   {name}  (visited → สีเทา)
บรรทัด: 📍 {area}[ · {"฿".repeat(price_level)}]   (ราคาเฉพาะร้าน, price_level 0 → ไม่แสดง)
โน้ต:   {note} ตัด 3 บรรทัด
ปุ่ม:   [🗺 Google Maps] [高德 Amap] [📷 รูป ({N})] [✓ ไปแล้ว | ↩ ยังไม่ไป]
```

- ไม่มีรูป → ไม่มี hero (การ์ดเตี้ยลง) และไม่มีปุ่มรูป; ป้ายสถานะย้ายไปต่อท้ายชื่อ
- **Maps:** 2 ปุ่ม [Google Maps] [高德 Amap] ผ่าน `mapButtons({ query: "{name} {area}", mapsLink: maps_link })` (ดู spec การเดินทาง หัวข้อ "ปุ่มแผนที่")
- **ไปแล้ว ⇄ ยังไม่ไป:** postback พก `visited` ปัจจุบัน → ถ้าไม่ตรงข้อมูลจริง (อีกคนกดแล้ว/แก้ในแอป) ไม่เปลี่ยน; ตอบการ์ดสถานที่ใบเดียวที่สถานะล่าสุด
- ทุก text node ว่าง → ซ่อน

### รูป — แตะขยาย

- **hero ทุกการ์ด** = แตะเปิดรูปเต็มจอในเบราว์เซอร์ LINE (ซูม/บันทึกได้)
- **[📷 รูป (N)]** → อัลบั้ม `buildPhotoAlbum` จาก spec แพลน — ทุกรูปในอัลบั้มแตะขยายได้เช่นกัน (≤ 12, เกิน → 11 + "ดูที่เหลือในแอป")

## Postback data

`a=<action>&k=<r|w>&id=<place_id>&f=<filters>&q=<query>&n=<page>&v=<visited>`
actions: `pl_list pl_photos pl_visit pl_unvisit amb_expense amb_place`
(`k`: r = restaurants, w = wishlist)

## Units

| Unit | หน้าที่ |
|---|---|
| `lib/line-places-parse.ts` | `parsePlacesQuery(text) → { kind, mustTry?, visited?, query, hasDigit } \| null` — pure |
| `lib/line-places.ts` | `normalizePlace(Restaurant \| WishItem) → Place` (รวม `must_try`/`star`, `price_level` เฉพาะร้าน), `filterPlaces`, `sortPlaces`, `topAreas(places, 4)`, `paginate(places, page)`, `placeMapsUrl` — pure |
| `lib/line-places-messages.ts` | `buildPlacesCarousel`, `buildPlaceBubble` → Flex JSON — pure |
| `app/api/line/webhook/route.ts` | router + I/O (อ่าน restaurants/wishlist, update visited) |

## Testing

- parse: คำหลักทั้ง 6, `ร้านอาหาร` ไม่ถูกตัดเป็น `ร้าน`+`อาหาร`, ตัวกรอง `ต้องลอง`/`ดาว`/`ยังไม่ไป`/`ไปแล้ว`, คำค้นที่เหลือ, `ขอดูร้าน`, ข้อความที่ไม่ใช่คำสั่ง → null, `กินข้าว 120` → hasDigit true
- sort: ติดดาว → ยังไม่ไป → ไปแล้ว
- paginate: ≤ 10, 11–21, หน้า 2 ไม่มีการ์ดหัว, ไม่เกิน 12 bubble ทุกหน้า
- topAreas: นับและเรียงถูก, ข้าม area ว่าง
- bubble: มี/ไม่มีรูป, hero action เป็น uri ไปรูปเต็ม, ราคาเฉพาะร้าน, Maps fallback, ไม่มี text node ว่าง
- toggle visited: postback สถานะไม่ตรง → ไม่เปลี่ยน
