# LINE: ดูแพลนเที่ยว (เฟส 2 — แพลน)

## Context

เฟส 1 (`2026-11-19-line-expense-capture-design.md`) ทำให้บันทึกค่าใช้จ่ายผ่าน LINE ได้
เฟสนี้ให้ดูแพลนของวัน/รายการในแพลนผ่าน LINE ได้ โดยไม่ต้องเปิดแอป

ผู้ใช้: กลุ่ม LINE 2 คน + บอท · ทริปเป้าหมาย = `status === "active"`

## ขอบเขตสิทธิ์

| การกระทำ | LINE | หมายเหตุ |
|---|---|---|
| ดูภาพรวม / รายละเอียด / รูป | ✅ | |
| ดูแพลนสำรอง | ✅ ดูอย่างเดียว | ไม่มีปุ่ม "ใช้แพลนนี้" — สลับแพลน active ทำในแอป |
| ติ๊กเสร็จ / ยกเลิกเสร็จ | ✅ | `status: planned ⇄ done` เท่านั้น |
| ข้าม / ย้ายวัน / แก้ข้อมูล | ❌ | ในแอปเท่านั้น |

## ข้อจำกัด

- reply เท่านั้น, ปุ่มใช้ postback (เหมือนเฟส 1)
- Flex: carousel ≤ 12 bubble, ข้อความใน bubble ต้องไม่ว่าง (ซ่อน node แทนการใส่ "")
- รูปใช้ URL สาธารณะ `${origin}/api/img/{id}` (เหมือนการ์ดยืนยันสลิป)

## คำสั่ง

prefix: `แพลน` หรือ `plan` (case-insensitive) ตามด้วย [วัน] [ลำดับ] — ทั้งสองไม่บังคับ

| พิมพ์ | ผล |
|---|---|
| `แพลน` | ภาพรวมวันนี้ |
| `แพลน พรุ่งนี้` / `แพลน เมื่อวาน` | ภาพรวมวันนั้น |
| `แพลน 20/11` / `แพลน 20 พ.ย.` / `plan 20 nov` | ภาพรวมวันที่ระบุ |
| `แพลน วันที่ 3` / `plan day 3` | วันที่ 3 ของทริป |
| `แพลน ศุกร์` | วันศุกร์แรกที่อยู่ในช่วงทริป นับจากวันนี้ (ไม่เจอ → ใกล้สุดในทริป) |
| `แพลน 1` / `#1` | รายละเอียดรายการที่ 1 ของ "วันที่ดูล่าสุด" (ไม่มี → วันนี้) |
| `แพลน พรุ่งนี้ 2` | รายละเอียดรายการที่ 2 ของพรุ่งนี้ |
| `ต่อไป` / `next` | รายละเอียดรายการถัดไปจากเวลาตอนนี้ |
| `ตอนนี้` / `now` | รายการที่ `time ≤ now < end_time`; ไม่มี → เหมือน `ต่อไป` |

**ลำดับในการแยก token:** ตัวเลขเดี่ยว 1–2 หลักที่ไม่ใช่ส่วนของวันที่ = ลำดับรายการ · `20/11` `วันที่ 3` = วัน

**"วันนี้" / "ตอนนี้"** ใช้ `trip.trip_timezone`

**"วันที่ดูล่าสุด"** เก็บต่อคน (key เดียวกับ session เฟส 1) ใน `line_sessions.data.lastPlanDate` — ไม่กระทบ flow ค่าใช้จ่าย

**ลำดับความสำคัญของ router** (ต่อจากเฟส 1): session ที่รอคำตอบ → คำสั่ง (`แพลน`, `plan`, `ต่อไป`, `ตอนนี้`, `#n`) → ข้อความมีตัวเลข = ค่าใช้จ่าย → อื่นๆ เงียบ (กลุ่ม)
→ `แพลน 20/11` จึงไม่ถูกตีเป็นค่าใช้จ่าย

## รายการที่แสดง

- items ของ `day_date` นั้น และ `plan_id` = แพลน active ของวัน (ไม่มี DayPlan rows → `plan_id === ""`)
- ดูแพลนสำรอง: items ของ `plan_id` นั้น
- เรียง `time` (ว่างไว้ท้าย) แล้ว `sort_order`
- **ลำดับ (1, 2, 3…) = ตำแหน่งหลังเรียง** ไม่ใช่ id — ใช้กับ `แพลน n` / `#n`
- status `moved` แสดงในวันเดิมพร้อม "ย้ายไป {moved_to_date}" (ไม่ดึงมาแสดงในวันปลายทาง — เหมือนในแอป)

## การ์ด 1 — ภาพรวมวัน (bubble เดียว)

```
หัว:   📅 วันที่ {n} · {DOW} {d} {เดือน}
       {ชื่อแพลน} · {k} รายการ [· มีแพลนสำรอง {m}]
แถว:   {ลำดับ} | {time}↵–{end_time} | {title}↵{place} | {ไอคอน}
ท้าย:  [◀ วันก่อน] [{ชื่อแพลนสำรอง}…] [วันถัดไป ▶]
```

**แถว**
- เวลา 2 บรรทัด: `09:00` / `–10:30`; ไม่มี end_time → บรรทัดเดียว; ไม่มี time → `—`
- บรรทัด 2 = `place` (ไม่มี → ซ่อน)
- ทั้งแถวเป็น postback → การ์ดรายละเอียด

**สีแถวตามสถานะ**
| สถานะ | แสดง |
|---|---|
| done | พื้นเขียวอ่อน + ✓ |
| planned และเป็น "ถัดไป" (เฉพาะดูวันนี้) | พื้นฟ้าอ่อน + ตัวหนา + บรรทัด 2 ต่อท้าย "· ต่อไป" |
| planned | ปกติ |
| skipped | ตัวเทา + ขีดฆ่าชื่อ + "· ข้าม" |
| moved | ตัวเทา + "· ย้ายไป 21/11" |

**ไอคอนท้ายแถว** (แสดงอันเดียว ตามลำดับความสำคัญ): สถานะ (✓ / ⏭ / ➡️) → 🎫 linked_booking → 🚇 linked_transport → 📷 มีรูป

**ปุ่มท้าย**
- `◀ วันก่อน` / `วันถัดไป ▶` — ซ่อนเมื่อชนขอบทริป
- ปุ่มชื่อแพลนสำรอง (≤ 2 ปุ่ม, เกินนั้นปุ่ม "แพลนอื่น" → quick reply ชื่อแพลน)
- ตอนดูแพลนสำรอง: หัวการ์ดเขียน "{ชื่อแพลน} (สำรอง — ดูอย่างเดียว)" และมีปุ่ม "กลับแพลนหลัก"

**ดูวันนี้แต่ทุกรายการผ่านไปแล้ว** → แถบท้าย "จบแพลนวันนี้แล้ว 🎉" + ปุ่ม [แพลนพรุ่งนี้]

**รายการเยอะ** — bubble ยาวได้ แต่ถ้า > 15 รายการ แสดง 15 แรก + "อีก {x} รายการ" ปุ่ม [ดูต่อ] (ภาพรวมหน้า 2)

## การ์ด 2 — รายละเอียดรายการ

```
hero:  รูปแรก (photo_ids[0]) — แตะ = เปิดรูปเต็ม (uri action ไป /api/img/{id})
       มุมขวาล่าง "แตะเพื่อขยาย"
หัว:   {ลำดับ} · {time}–{end_time}          [badge สถานะ]
       {title}
       📍 {place}
โน้ต:  {notes} ตัด 3 บรรทัด + "อ่านต่อ" (postback → ส่งโน้ตเต็มเป็น text message)
เดินทาง (ถ้ามี linked_transport_id):
       {mode} · {from} → {to}
       ออก {depart_time} · {duration} · {price_amount} {price_currency}
       แตะ → การ์ดการเดินทางเต็ม (ออกแบบในหัวข้อการเดินทาง)
จอง (ถ้ามี linked_booking_id):
       {vendor} · {ref_no ตัวใหญ่ monospace}
       แตะ → การ์ดการจองเต็ม (ออกแบบในหัวข้อการจอง)
ปุ่ม:  [🗺 Google Maps] [高德 Amap] [📷 ดูรูปทั้งหมด (N)] [✓ เสร็จ | ↩ ยังไม่เสร็จ]
       [◀ ก่อนหน้า] [ภาพรวม] [ถัดไป ▶]
```

- ทุกส่วนที่ไม่มีข้อมูล → ซ่อนทั้งส่วน (ไม่มีรูป → ไม่มี hero และไม่มีปุ่มดูรูป)
- **Maps:** 2 ปุ่ม [Google Maps] [高德 Amap] ผ่าน `mapButtons({ query: place || title, mapsLink: maps_link })` (ดู spec การเดินทาง หัวข้อ "ปุ่มแผนที่"); ไม่มีทั้ง maps_link และ place → ซ่อนทั้งคู่
- **linked id ที่หาไม่เจอ** (ถูกลบ) → ซ่อนส่วนนั้นเงียบๆ
- **ปุ่มเสร็จ:** แสดงเฉพาะ status `planned` (→ "✓ เสร็จ") และ `done` (→ "↩ ยังไม่เสร็จ"); `skipped` / `moved` ไม่มีปุ่ม
  - กดแล้ว update `status`, ตอบการ์ดรายละเอียดใบใหม่ (สถานะใหม่)
  - postback ตรวจ status ปัจจุบันก่อน — ถ้าเปลี่ยนไปแล้ว (เช่นอีกคนกดก่อน / แก้ในแอป) ไม่ทำ แสดงการ์ดสถานะล่าสุด
- **ก่อนหน้า / ถัดไป** — ตามลำดับในแพลนเดียวกัน; ชนขอบ → ซ่อนปุ่ม

## การ์ด 3 — อัลบั้มรูป

- กด "ดูรูปทั้งหมด" → carousel bubble ละรูป (hero image + "{i}/{N} · {title}")
- แตะรูป → เปิดรูปเต็ม (uri)
- N > 12 → 11 รูปแรก + bubble สุดท้าย "ดูอีก {N-11} รูปในแอป" (uri → หน้าแพลนวันนั้นในแอป)

## ข้อผิดพลาด / ไม่มีข้อมูล

| สถานการณ์ | ตอบ |
|---|---|
| วันนั้นไม่มีรายการ | "{วันที่} ยังไม่มีแพลน" + [เปิดแอป] + ปุ่มวันก่อน/ถัดไป |
| วันอยู่นอกช่วงทริป | "ทริปอยู่ระหว่าง {start}–{end}" + quick reply วันในทริป (≤ 13) |
| ลำดับเกิน (`แพลน 9` มี 5) | "วันนี้มี 5 รายการ" + การ์ดภาพรวม |
| อ่านวันไม่ออก | "ไม่เข้าใจวันที่" + quick reply [วันนี้][พรุ่งนี้] + วันในทริป |
| ไม่มีทริป active | ข้อความเดิมจากเฟส 1 |
| postback อ้าง item ที่ถูกลบ | "รายการนี้ถูกลบไปแล้ว" + การ์ดภาพรวมวันนั้น |

## Postback data

`a=<action>&d=<day_date>&p=<plan_id>&i=<item_id>&n=<page>`
actions: `plan_overview plan_detail plan_photos plan_note plan_done plan_undone plan_alt`

## Units

| Unit | หน้าที่ |
|---|---|
| `lib/line-date-parse.ts` | `parsePlanQuery(text, { trip, today }) → { date?, index?, error? }` — วัน/ลำดับ, ไทย+อังกฤษ — pure (เฟสอื่นใช้ซ้ำ) |
| `lib/line-plan.ts` | `itemsForDay(items, dayPlans, date, planId?)`, `nextItem(items, nowHHMM)`, `currentItem(...)`, `mapsUrl(item)` — pure |
| `lib/line-plan-messages.ts` | `buildPlanOverview`, `buildPlanDetail`, `buildPhotoAlbum` → Flex JSON — pure |
| `app/api/line/webhook/route.ts` | router + I/O (อ่าน itinerary / day_plans / transports / bookings, update status) |

## Testing

- `parsePlanQuery`: `แพลน`, `plan`, พรุ่งนี้/เมื่อวาน, `20/11`, `20 พ.ย.`, `20 nov`, `วันที่ 3`, `day 3`, ชื่อวัน, `แพลน 2`, `แพลน พรุ่งนี้ 2`, `#1`, นอกช่วงทริป, อ่านไม่ออก
- `itemsForDay`: วันไม่มี DayPlan, วันมีแพลนสำรอง (เลือก active / เลือก plan_id), เรียงเวลาว่างไว้ท้าย
- `nextItem` / `currentItem`: ก่อนรายการแรก, ระหว่างรายการ, หลังรายการสุดท้าย, ข้าม done/skipped/moved
- `buildPlanOverview`: สีตามสถานะ, ไม่มี end_time, ไม่มี place, ไม่มี text node ว่าง, ปุ่มวันซ่อนที่ขอบทริป, > 15 รายการ
- `buildPlanDetail`: ซ่อนส่วนที่ว่าง, ปุ่มเสร็จตาม status, Maps fallback, linked id ที่หาไม่เจอ
- `buildPhotoAlbum`: N ≤ 12, N > 12

## Out of scope

- สลับแพลน active, ข้าม, ย้ายวัน, แก้ไขรายการ (แอปเท่านั้น)
- การ์ดการจอง / การเดินทางแบบเต็ม — ออกแบบในหัวข้อของตัวเอง (การ์ดนี้แค่ลิงก์ไป)
