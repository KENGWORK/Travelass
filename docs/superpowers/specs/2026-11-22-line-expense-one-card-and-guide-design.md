# LINE: ถามที่ขาดทีเดียว + บันทึกอัตโนมัติ + คำสั่ง คู่มือการใช้งาน

## Context

ปรับจากของที่ deploy แล้ว (`f64d136`) หลังทดลองคิด flow จริง:
1. เดิมบอทถามทีละข้อ (สกุลเงิน → คนจ่าย → หาร …) → เปลี่ยนเป็น **การ์ดใบเดียวถามทุกข้อที่ขาด**
2. เดิมต้องกด ✅ ยืนยัน → เปลี่ยนเป็น **บันทึกอัตโนมัติทันทีที่ครบ**
3. เพิ่มคำสั่ง **`คู่มือการใช้งาน`** (และ `คู่มือ`)
4. ทริป: **ใช้ทริปที่สถานะ "กำลังเที่ยว"** เหมือนเดิม — ไม่เพิ่มคำสั่ง `ทริป` ไม่ถามเมื่อมีหลายทริป

ไฟล์นี้ทับส่วน "Flow" ของ `2026-11-19-line-expense-capture-design.md` และส่วน router/menu ของ `2026-11-21-line-bot-shared-design.md` เฉพาะที่ขัดกัน
การแยกชั้น (parse / flow / messages / handler) ยังเหมือนเดิม — pure modules ห้ามมี I/O

## ข้อสมมติที่ต้องให้ผู้ใช้ยืนยัน

- A1: "ใช่" ข้อ 2 = การ์ดใบเดียวที่มีปุ่มทุกข้อ (ไม่ใช่ข้อความให้พิมพ์ตอบอย่างเดียว) และรับ `คู่มือ` สั้นๆ ด้วย
- A2: ชื่อทริปที่ใช้อยู่แสดงเป็นบรรทัดเล็กท้ายการ์ดค่าใช้จ่าย ("ทริป HKG กวางโจว") เพื่อให้เห็นว่าบันทึกลงทริปไหน

## 1. การ์ดถามที่ขาดทีเดียว ("missing card")

### ฟิลด์ที่ต้องครบ

| ฟิลด์ | มาจาก | ถ้าขาด |
|---|---|---|
| amount | parse จากข้อความ | แถว "พิมพ์ยอด" (พิมพ์ตอบ) |
| currency | parse / ยืนยันแล้ว | ปุ่ม [trip_currency] [home_currency] |
| payer | ชื่อ LINE ตรงสมาชิก / parse `@ชื่อ` | ปุ่มชื่อสมาชิก |
| split | parse (`หาร` / `ไม่หาร` / `ฝาก N`) | ปุ่ม [ไม่หาร] [หารเท่า] [หารไม่เท่า] |
| owed | เฉพาะ split=unequal | แถว "พิมพ์ยอดที่ฝากจ่าย" (พิมพ์ตอบ) |
| category / note | เดา / ข้อความที่เหลือ | ไม่ถาม |

ลำดับแถวในการ์ด: ยอด → สกุลเงิน → คนจ่าย → หาร → (ยอดฝากจ่าย)

### หน้าตาการ์ด (Flex bubble เดียว)

```
💸 {amount} {currency} · {note}      ← เฉพาะที่รู้แล้ว (ไม่มี amount → "รับสลิปแล้ว 📸" ถ้ามีรูป, ไม่งั้น "รายการใหม่")
เหลืออีก {n} อย่าง

✓ สกุลเงิน   HKD                     ← ตอบแล้ว: แสดงค่า (แตะ = เปลี่ยน)
คนจ่าย       [เก่ง] [โอ]              ← ยังไม่ตอบ: ปุ่ม
หาร          [ไม่หาร] [หารเท่า] [หารไม่เท่า]
ยอด          พิมพ์ตัวเลข เช่น 120     ← ยังไม่ตอบ + ไม่มีปุ่ม

พิมพ์ตอบทีเดียวก็ได้ เช่น "HKD เก่ง หารเท่า"
[🗑 ยกเลิก]
ทริป {trip.name}                      ← A2
```

- แถว owed แสดงเมื่อเลือก "หารไม่เท่า" แล้ว: `ยอดที่ฝากจ่าย — พิมพ์ตัวเลข เช่น ฝาก 20` (ยังไม่รู้ amount → "ใส่ยอดรวมก่อน")
- ปุ่ม [🗑 ยกเลิก] = พฤติกรรมเดิมของ `ยกเลิก` กลางทาง (ถาม ลบทิ้ง / เก็บไว้กรอกทีหลัง)
- ไม่มีปุ่ม ↩ ย้อนอีกแล้ว: แตะแถวที่ตอบแล้ว = ล้างค่าฟิลด์นั้นแล้วส่งการ์ดใหม่

### ตอบได้ 2 แบบ ปนกันได้

**ปุ่ม:** กด 1 ครั้งต่อ 1 ฟิลด์ → บอทอัปเดตแล้วส่งการ์ดใหม่ (LINE แก้การ์ดเดิมไม่ได้) การ์ดเก่าใช้ไม่ได้ ดู "ปุ่มเก่า"

**พิมพ์ครั้งเดียวหลายฟิลด์:** `interpretBundle(text, missing, ctx)` อ่านทุก token ในข้อความ:
- สกุลเงิน (`resolveCurrency`) · ชื่อสมาชิก (ตรงทั้งคำ หรือ `@ชื่อ`) · คำหาร (`parseSplitWord`, `ฝาก N`) · ตัวเลข
- ตัวเลขเปล่า: ถ้า amount ยังขาด → amount; ถ้า amount รู้แล้วและ split=unequal ยังไม่มี owed → owed; ไม่งั้นไม่ใช้
- token ที่ไม่รู้จัก: ถ้าอย่างน้อย 1 ฟิลด์ถูกอ่านได้ → ข้ามเงียบๆ; ถ้าไม่ได้ฟิลด์ไหนเลย → ส่งการ์ดเดิมซ้ำพร้อมข้อความ "ไม่เข้าใจ ลองกดปุ่ม หรือพิมพ์ เช่น HKD เก่ง หารเท่า"
- ค่าที่ขัดกัน (เช่นสองสกุลเงิน) → ใช้ตัวแรก
- owed ตรวจด้วย `validateOwed` เดิม (0 → ถามเปลี่ยนเป็นไม่หาร, เกิน → แจ้งเกินยอด) — ข้อความเตือนขึ้นเหนือการ์ดที่ส่งใหม่

### บันทึกอัตโนมัติ

เมื่อทุกฟิลด์ที่ต้องครบ → `finalize` (คำนวณ fx, amount_thb, splits) → `pending=false` → ลบ flow session → ตอบ **การ์ดบันทึกแล้ว** แทนการ์ดถาม:

```
✅ บันทึกแล้ว
{amount} {currency} (~{thb}฿) · {หมวด}
👤 {payer} จ่าย · {สรุปหาร}
📝 {note}
(ถ้า fx ดึงไม่ได้: ⚠️ ดึงเรตไม่ได้ ใช้ 1:1 แก้ในแอป)
[✏️ แก้] [🗑 ลบ]
ทริป {trip.name}
```

- ไม่มีปุ่ม ✅ ยืนยันอีกต่อไป และไม่มี step `summary` สำหรับ draft ใหม่
- **✏️ แก้** → ปุ่มเลือกฟิลด์ [ยอด][สกุลเงิน][คนจ่าย][หาร][หมวด][โน้ต] → ถามเฉพาะข้อนั้น → **บันทึกทับทันที** แล้วส่งการ์ดบันทึกแล้วใบใหม่ (รายการยืนยันแล้ว ไม่ย้อนเป็น pending)
- **🗑 ลบ** = flow เดิมของรายการที่ยืนยันแล้ว: ถาม [ลบรายการนี้][ไม่ลบ] ก่อน (ไม่เปลี่ยน)
- แก้ยอดที่มี split อยู่: คงกฎเดิม — คำนวณ split ใหม่โดยคง `paid` / `paid_slip_photo_ids` ของคนเดิม
- `แก้ล่าสุด` = เปิดการ์ดบันทึกแล้วของรายการล่าสุด (เดิมเปิด summary)

### ปุ่มเก่า / หลายคน

- postback ทุกปุ่มพก `e` (expense id) และ `v` (revision ของการ์ด เพิ่มทีละ 1 ทุกครั้งที่ข้อมูลเปลี่ยน) เก็บใน `session.data.rev`
- `e` หรือ `v` ไม่ตรง session ปัจจุบัน → ไม่ทำอะไร ส่งการ์ดปัจจุบันซ้ำพร้อม "ปุ่มนี้หมดอายุแล้ว"
- session แยกตามคนเหมือนเดิม — อีกคนกดปุ่มบนการ์ดของเรา = ปุ่มเก่าของเขา

### สิ่งที่คงเดิม

TTL 30 นาที · draft-first (สร้าง expense pending ตั้งแต่ข้อความแรก) · `ยกเลิก` / `ทำต่อ` / conflict prompt · รูปแนบเข้า flow ที่ค้าง · เดาหมวด · parse ข้อความบรรทัดเดียว · ทริป = `status === "active"` ตัวแรก

### สิ่งที่ลบ

step `summary` สำหรับ draft ใหม่, `confirm` action, ปุ่ม ↩ ย้อน, ข้อความถามทีละข้อ (`questionMessage` แยกต่อ step → แทนด้วย `missingCard`)

## 2. คำสั่ง `คู่มือการใช้งาน`

| พิมพ์ | ผล |
|---|---|
| `คู่มือการใช้งาน` · `คู่มือ` | carousel: สารบัญ + 1 ใบต่อหัวข้อ |
| `คู่มือ ค่าใช้จ่าย` · `คู่มือ แพลน` · `คู่มือ จอง` (หรือ `ตั๋ว`/`เอกสาร`) · `คู่มือ ร้าน` (หรือ `ที่เที่ยว`) · `คู่มือ ข้อมูล` (หรือ `โน้ต`) · `คู่มือ เดินทาง` | ใบของหัวข้อนั้นใบเดียว |

- ตัดคำนำหน้า `ขอดู`/`ขอ` ได้เหมือนคำสั่งอื่น · ไม่ต้องมีทริป active · ในกลุ่มตอบเสมอ (คำสั่งชัดเจน)
- เป็น **view command**: `isViewCommand` ต้องรับ → ระหว่างกรอกค่าใช้จ่ายพิมพ์ `คู่มือ` ได้โดยรายการที่ค้างอยู่ไม่เสีย และไม่ถูกจับเป็นโน้ต
- ไม่มีตัวเลข → ไม่ชนกฎ ambiguity

**หัวข้อ (7 ใบ + สารบัญ):** บันทึกค่าใช้จ่าย · แพลน · ตั๋ว/การจอง · ร้านและที่เที่ยว · ข้อมูลด่วนและโน้ต · การเดินทาง · อื่นๆ (เมนู, ทริปที่ใช้อยู่ = "บอทใช้ทริปที่สถานะ กำลังเที่ยว", ข้อจำกัดว่าแก้ไขทำในแอป)

**ใบของหัวข้อ:** ชื่อหัวข้อ · ตารางคำสั่ง (พิมพ์ → ได้อะไร) 4–6 บรรทัด · ตัวอย่าง 2–3 ตัว
- ปุ่ม **[ลองเลย]** (action `message`) เฉพาะคำสั่งดูข้อมูลที่ไม่มีผลข้างเคียง: `แพลน` `ต่อไป` `จอง` `ร้าน` `ที่เที่ยว` `ข้อมูล` `โน้ต` `เดินทาง`
- ใบค่าใช้จ่าย **ไม่มี [ลองเลย]** (กดแล้วจะบันทึกจริง) ใช้ปุ่ม **[คัดลอกตัวอย่าง]** (clipboard) แทน

**เชื่อมกับเมนู:** การ์ดใบแรกของ `เมนู` เพิ่มปุ่ม [คู่มือการใช้งาน] (postback `menu_go&t=guide`) · `HINT_TEXT` เปลี่ยนเป็น "ไม่เข้าใจ ลองพิมพ์ เช่น 120 บาท ข้าว หรือพิมพ์ คู่มือการใช้งาน"

**Route ใหม่ใน router:** `{ kind: "guide"; topic: GuideTopic | null }` — dispatch จัดการเอง (เหมือน `menu`) ไม่ต้องมี handler ฟีเจอร์

### Units

| Unit | หน้าที่ |
|---|---|
| `lib/line-guide.ts` (ใหม่, pure) | `GUIDE_TOPICS` (ข้อมูลหัวข้อ/คำสั่ง/ตัวอย่าง), `matchGuide(text) → { topic } \| null`, `buildGuideMessage(topic \| null)` |
| `lib/line-router.ts` | เพิ่ม `guide` route + ใน `isViewCommand`; `คู่มือ`/`คู่มือการใช้งาน` match คำยาวก่อน |
| `lib/line-menu.ts` | ปุ่มคู่มือ, `HINT_TEXT`, `menuGoRoute` รับ `t=guide` |
| `lib/line-dispatch.ts` | route `guide` → `buildGuideMessage` |
| `docs/line-bot-how-to.md` | เพิ่มหัวข้อคู่มือ + อัปเดตวิธีบันทึกค่าใช้จ่ายเป็น flow ใหม่ |

## 4. Testing

- `missingFields`: ครบ/ขาดทุกชุดย่อย, payer จาก LINE name, split=unequal ต้องมี owed, amount ยังไม่มี → owed ถามไม่ได้
- `interpretBundle`: `HKD เก่ง หารเท่า`, `120`, `ฝาก 20`, ตัวเลขเปล่ากับสถานะต่างๆ, token แปลกปน, ค่าขัดกัน, ไม่ได้ฟิลด์ไหน → null
- auto-finalize: พิมพ์ครั้งเดียวครบ → saved ทันที (pending=false, splits ถูก), กดปุ่มทีละฟิลด์ → saved เมื่อฟิลด์สุดท้าย, fx ล้มเหลว → saved + คำเตือน
- ปุ่มเก่า (rev ไม่ตรง), `x_clear` ล้างค่า, แก้รายการยืนยันแล้วบันทึกทับทันที, ลบรายการยืนยันแล้วต้องถามก่อน, คง paid ของ split
- `missingCard`: ไม่มี text node ว่าง, ปุ่มเฉพาะฟิลด์ที่ขาด, ข้อความ A2 ชื่อทริป
- guide: ทุกหัวข้อมี ≥ 1 คำสั่ง, **ทุก keyword ที่ router รู้จักอยู่ในคู่มืออย่างน้อย 1 ที่** (เทสต์สอดคล้อง), ใบค่าใช้จ่ายไม่มี action `message`, `คู่มือ จอง`/`คู่มือ ตั๋ว` → topic เดียวกัน, `isViewCommand("คู่มือ")` จริง
- router: `คู่มือการใช้งาน` / `คู่มือ แพลน` → guide, ระหว่างมี flow ค้างยังเป็น guide

## Out of scope

- คำสั่ง `ทริป` / ถามเลือกทริป
- ตัวเลือกบันทึกโดยไม่ครบฟิลด์
- สรุปค่าใช้จ่าย / แปลงค่าเงิน / สรุปหนี้ (ออกแบบต่อ)
