# LINE: ดูตั๋ว / การจอง / เอกสาร (เฟส 2 — การจอง)

## Context

ต่อจาก `2026-11-19-line-expense-capture-design.md` (เฟส 1) และ `2026-11-19-line-plan-view-design.md`
ให้เรียกดูการจอง (`Booking`) ผ่าน LINE ได้ทันที — ใช้โชว์เลขจอง/ตั๋วที่เคาน์เตอร์ โรงแรม หน้าประตู

ผู้ใช้: กลุ่ม LINE 2 คน + บอท · ทริปเป้าหมาย = `status === "active"`

## ขอบเขต

- **ดูอย่างเดียว** — แก้ไข / ติ๊กจ่าย ทำในแอป
- เฉพาะ `bookings` — ไม่รวม `transports` (MTR/บัสในแผนการเดินทาง → หัวข้อการเดินทาง)
- reply เท่านั้น, ปุ่ม postback (เหมือนเฟสก่อน)

## คำสั่ง

**คำหลัก 3 คำเท่านั้น:** `จอง` `ตั๋ว` `เอกสาร` (ไม่มีคำอังกฤษ)

**Normalize ก่อน match:** ตัดคำนำหน้า `ขอดู` `ขอ` `การ` `ของ` (ซ้อนกันได้) และช่องว่าง
→ `ขอดูเอกสารการจองโรงแรม` → `เอกสาร` + `จอง` + `โรงแรม`

ข้อความเข้าข่ายคำสั่งการจองเมื่อ **หลัง normalize ขึ้นต้นด้วยคำหลัก**

**คำบอกประเภท** (ติดกันหรือเว้นวรรค, จับที่ไหนก็ได้หลังคำหลัก):

| คำ | `BookingType` |
|---|---|
| เครื่อง เครื่องบิน บิน ไฟลต์ | `flight` |
| โรงแรม ที่พัก | `hotel` |
| รถ | `car` |
| กิจกรรม ทัวร์ สวนสนุก | `activity` |

**คำบอกวัน:** ใช้ `parsePlanQuery` จาก spec แพลน (วันนี้ พรุ่งนี้ `21/11` `วันที่ 3` ฯลฯ) → กรองการจองที่ `date_from ≤ วัน ≤ date_to` (ไม่มี date_to → `date_from === วัน`)

**คำที่เหลือ** = คำค้น → match (contains, case-insensitive) กับ `vendor` `ref_no` `detail` `notes`

ตัวอย่าง:
| พิมพ์ | ประเภท | วัน | คำค้น |
|---|---|---|---|
| `จอง` | — | — | — |
| `ตั๋วเครื่อง` | flight | — | — |
| `เอกสารการจองโรงแรม` | hotel | — | — |
| `การจองรถ` / `ตั๋วรถ` | car | — | — |
| `ตั๋ว ดิสนีย์` | — | — | ดิสนีย์ |
| `จอง พรุ่งนี้` | — | พรุ่งนี้ | — |

## ชนกับการบันทึกค่าใช้จ่าย

ข้อความเข้าข่ายคำสั่งการจอง **และมีตัวเลขอย่างน้อย 1 ตัว** (รวมวันที่ `21/11` และเลขในรหัส `CX703`) → **ถามกลับทุกครั้ง**:

```
"ตั๋วรถ 50" — จะทำอะไร?
[💸 บันทึกค่าใช้จ่าย] [🎫 ค้นการจอง]
```

- postback เก็บข้อความต้นฉบับ (เข้ารหัสใน data, ตัดที่ 200 ตัวอักษร)
- บันทึกค่าใช้จ่าย → เข้า flow เฟส 1 ด้วยข้อความนั้น
- ค้นการจอง → ทำตามกฎด้านบน
- **ข้อยกเว้น:** ถ้ามี session เฟส 1 ที่รอตัวเลขอยู่ → ถือเป็นคำตอบของ session (ลำดับ router เดิม)

**ลำดับ router (อัปเดต):** session ที่รอคำตอบ → คำสั่งแพลน → คำสั่งการจอง (ไม่มีตัวเลข) / ถามกลับ (มีตัวเลข) → ข้อความมีตัวเลข = ค่าใช้จ่าย → อื่นๆ เงียบ (กลุ่ม)

## ผลค้น

| เจอ | ตอบ |
|---|---|
| 1 | การ์ดรายละเอียด |
| ≥ 2 | การ์ดรายการ (เฉพาะที่ตรง) |
| 0 | "ไม่เจอ '{คำค้น}'" + ปุ่ม 4 ประเภท |
| ทริปไม่มีการจองเลย | "ทริปนี้ยังไม่มีการจอง" + [เปิดแอป] |

## การ์ด 1 — รายการ (bubble เดียว)

```
หัว:   🎫 {ชื่อตัวกรอง | การจองทั้งหมด} · {n}
       เรียงตามวัน · ที่ผ่านไปแล้วอยู่ท้าย
กลุ่ม: หัววัน "{DOW} {d} {เดือน}[ · วันนี้]"  … สุดท้าย "ผ่านไปแล้ว"
แถว:   {ไอคอนประเภท} | {ชื่อ}↵{time_from} · {vendor} · {ref_no} | {รูปย่อ}
ท้าย:  [✈️ เครื่องบิน] [🏨 โรงแรม] [🚗 รถ] [🎡 กิจกรรม]
```

- **ชื่อแถว:** `detail` บรรทัดแรก (ตัด 30 ตัวอักษร) ถ้าว่าง → `vendor`
- **โรงแรม:** บรรทัด 2 = `{date_from}–{date_to} · {คืน} คืน[ · กำลังพัก]`
- **เรียง:** `date_from` + `time_from`; "ยังไม่ผ่าน" = `(date_to || date_from) ≥ วันนี้` อยู่บน, ผ่านแล้วอยู่ล่าง (สีเทา, เรียงใหม่→เก่า)
- **วันนี้** (date ครอบวันนี้) → พื้นฟ้าอ่อน
- **รูปย่อ** = `slip_photo_ids[0]` ถ้ามี (40×40), ไม่มี → ช่องว่าง
- แถวทั้งแถว = postback → การ์ดรายละเอียด
- **ไม่มีป้ายสถานะการจ่าย**
- > 15 รายการ → 15 แรก + [ดูต่อ]

## การ์ด 2 — รายละเอียด

```
hero:  slip_photo_ids[0] — แตะ = เปิดรูปเต็ม · "แตะเพื่อขยาย"
หัว:   {ไอคอน} {ชื่อประเภท}
       {ชื่อ}
       {vendor}
เลขจอง: กล่องกลาง ref_no ตัวใหญ่ monospace
วันเวลา:
  hotel:  เช็คอิน {date_from}[ {time_from}] → เช็คเอาท์ {date_to} · {คืน} คืน
  อื่นๆ:  {DOW} {date_from} · {time_from}  [ถึง {date_to} ถ้าต่างวัน]
          นับถอยหลัง: "อีก {d} วัน" / "อีก {h} ชม." / "วันนี้" / "ผ่านไปแล้ว"
รายละเอียด: detail (เต็ม, wrap)
ค่าใช้จ่าย: {amount} {currency}[ (~{amount_thb}฿) ถ้าไม่ใช่ THB] · {payer}จ่าย
โน้ต:   notes ตัด 3 บรรทัด + "อ่านต่อ"
ปุ่ม:  [📋 คัดลอกเลขจอง] [📷 ดูรูปทั้งหมด (N)]
       [📅 ดูในแพลน] [กลับรายการ]
```

- ทุกส่วนที่ว่าง → ซ่อน (ไม่มี ref_no → ไม่มีกล่องเลขจองและปุ่มคัดลอก; ไม่มีรูป → ไม่มี hero/ปุ่มรูป; amount 0 → ไม่มีส่วนค่าใช้จ่าย)
- **ไม่แสดง** `paid`, `pay_timing`
- **คัดลอกเลขจอง:** Flex `clipboard` action (`clipboardText: ref_no`) — LINE เวอร์ชันเก่าที่ไม่รองรับ: LINE แสดงข้อความ fallback; เพิ่มเลขจองเป็น text node ที่ select ได้อยู่แล้วในกล่อง
- **ดูในแพลน:** หา itinerary ที่ `linked_booking_id === booking.id` → 1 อัน: การ์ดรายละเอียดแพลน; หลายอัน: quick reply เลือก; ไม่มี → ซ่อนปุ่ม
- **กลับรายการ:** การ์ดรายการด้วยตัวกรองเดิม (เก็บใน postback)

## Testing

- normalize: `จอง`, `ตั๋วเครื่อง`, `เอกสารการจองโรงแรม`, `ขอดูการจองรถ`, `ตั๋วรถ`, `ตั๋ว ดิสนีย์`, `จอง พรุ่งนี้`, คำที่ไม่ใช่คำสั่ง (`โรงแรมสวยมาก`) → isBooking false
- hasDigit: `ตั๋วรถ 50`, `จอง 21/11`, `ตั๋ว CX703` → true
- filter: ตามประเภท, วันในช่วง hotel, คำค้นใน vendor/ref/detail/notes
- sort: upcoming/past แยกถูก, hotel ที่กำลังพัก = upcoming
- nights, countdown (วัน/ชม./วันนี้/ผ่านแล้ว) ตาม trip timezone
- buildBookingDetail: ซ่อนส่วนว่าง, ไม่มี paid/pay_timing ใน JSON, clipboard action มี ref_no, ไม่มี text node ว่าง
- ambiguity prompt: postback ทั้งสองปุ่มพกข้อความต้นฉบับ
